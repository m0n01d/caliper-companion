# SPEC §8a A16 (Motion) — pre-build review, 2026-09-18, commit `e3e321e`

**Verdict: BUILD WITH EDITS, split in two.** The direction is right (View Transitions for pushes/pops, CSS enter animations for take-overs, canvas eases through the frame loop that already exists). Four things in the text would ship as a slide that still runs under reduced motion, a Back double-tap that degrades into a crossfade, a page on which *every* route transition silently becomes a cut, and a segmented control that flies off its screen during pushes. Platform claims were checked against MDN/Chrome docs/caniuse and **measured in the repo's own Playwright Chromium 148** (scratchpad probe, `file://` page; WebKit cannot launch here, so every WebKit statement below is "per docs, unverified"). Code claims are checked against `Tea.res`, `Route.res`, `Main.res`, the pages and the specs. Paste-ready text in §4, the e2e list in §5.

## 2. Judgements asked for

1. **`Route.subscribe` wrap.** Sound, with S1's correction: cmds run inside the flush but in today's order; `flushSync` from a native listener or a VT callback is allowed (react.dev: only render/effects are forbidden; it does force the commit before returning). Exact shape: `Motion.transition(~nav, dispatch, msg)` in §4, used by `Route.subscribe` only (B3 removes the other callers).
2. **Direction.** Depth is enough for every reachable pair except Capture → Annotate (S2: make Annotate 12) and same-depth folder hops. The Back gesture is a `hashchange` like any other; depth gives `pop` for Part → Parts, Debug → Settings, Settings → root, Parts(Miata/Interior) → Parts(Miata). Part → Parts(folder) after a move: 10 → 1+d, `pop`. Search results: root → any folder is `push`; from a folder to a sibling is `fade`. The `history.state` index (§4 J2) fixes the last case and Forward; optional.
3. **`data-nav` races.** B2. Generation counter + clear on both branches; unsupported = no attribute at all.
4. **DOM timing.** Callback runs after rAF (B2), so the model lags the URL by ~1 frame even under reduce. `Canvas.setScrollTop` is fine (S3). Existing specs: every post-navigation read is `page.url()` (sync, URL already changed), a retrying `expect`, or an auto-waiting locator; the "first Tab" tests all `reload()` first (a11y.spec:84-89, :140-147, :160-167, :323-331). None races.
5. **Take-overs vs focus/sticky.** `focusWhenReady` retries over 6 rAFs (PartsList.res:236-263); `focus()` on an element inside a `translateY` ancestor works, and Safari's focus-scroll lands ≤ 24 px early then the element arrives — fine. Sticky is safe: `.shell-topbar` and `.shell-footer` are direct children of `.shell` (Shell.res:30-74); the form, picker and rows live inside `<main>`; the spec animates `.shell-footer` itself (its own transform does not break its own stickiness). Nothing in A16 transforms `.shell` or `.app-frame` — say so in the text so it stays that way.
6. **Segmented.** Not worth VT: B3 (uniqueness + lift-out), the page is non-interactive for the transition, iOS 17 gets nothing, and the CSS indicator is ~20 lines with options already `flex: 1 1 0` (global.css:946-947). §4 has it.
7. **Canvas ease.** `drawScene` is paint-on-change (`useLayoutEffect` keyed on scene fields, Annotate.res:1390-1405); animation frames come from `frames` — a per-animation rAF loop that ends at progress 1 and single-ticks under reduced motion. Cheapest ease: `Viewport.ease` applied to `progress` inside `Draw.snapRing` (one line). Pill settle = a new tick (S10); reading-field ring = CSS `:focus` keyframe.
8. **Playwright.** `reducedMotion` emulates the media feature only; the API still runs (B4). Assertions that could race: none existing; the new spec's `data-nav`/pseudo reads must come from the in-page log (§4 J8). Counter via `addInitScript`: sound if it patches `Document.prototype.startViewTransition` and calls the original with `this`; our `@send` binding goes through it, and the `@get` feature check sees the wrapper.
9. **Scope.** Two waves, disjoint files. **A16a** (sonnet): tokens, `Motion.res` + bindings + `Route.subscribe` + `Main` scroll reset, nav CSS + reduced-motion rule, take-over rises, press scale, `playwright.config.js`, `motion.spec.js`, DESIGN/LOGBOOK. Risk: low-medium (B1/B2 fixed in text). **A16b** (sonnet, after a): segmented indicator (`Ui.res`, global.css), `part-select` stagger, snap-ring ease, reading ring fade. Risk: low. **Drop** for show-off: rows appearing, picker-option stagger, check-badge pop, pill settle, Snap-pill transition, the handle "keep".
10. **Ambiguities.** §4 J10.

## 3. Verdict

Build A16a with §4 applied, then A16b. B1–B4 are correctness of the mechanism (they would ship as the opposite of the reduced-motion promise and as invisible transitions); S1–S3 are what the runtime actually does; the rest trims the list to what a fresh install will show.

## 4. Spec edits (paste over the matching A16 text)

**B2/S1 — replace the `Route.subscribe` bullet:**
> `src/bindings/WebApi.res` gains `ViewTransition` (`type t`, `@get startFn: Dom.document => Nullable.t<fn>` for detection, `@send start: (Dom.document, unit => unit) => t`, `@get finished: t => promise<unit>`) and `@module("react-dom") external flushSync: (unit => unit) => unit`. New `src/app/Motion.res`:
> ```rescript
> let gen = ref(0)
> let transition = (~nav: string, dispatch: 'msg => unit, msg: 'msg): unit =>
>   if !WebApi.ViewTransition.supported() { dispatch(msg) } else {
>     gen := gen.contents + 1
>     let mine = gen.contents
>     WebApi.Document.setDataNav(nav) // before `start`: the old capture and the CSS must see it
>     let clear = _ => { if gen.contents == mine { WebApi.Document.removeDataNav() }; Promise.resolve() }
>     WebApi.ViewTransition.start(WebApi.ViewTransition.document, () => WebApi.flushSync(() => dispatch(msg)))
>     ->WebApi.ViewTransition.finished->Promise.then(clear)->Promise.catch(clear)->ignore

> ```
> `Route.subscribe` keeps `let prev = ref(current())` and on `hashchange` computes `next`, `nav = direction(prev.contents, next)`, sets `prev := next`, then `Motion.transition(~nav, dispatch, toMsg(next))`.
