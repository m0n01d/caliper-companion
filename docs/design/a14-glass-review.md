# SPEC §8a A14 (Hybrid glass) — pre-build review, 2026-09-18, commit `2da1bbc`

**Verdict: BUILD WITH EDITS.** The direction is right (mono tokens from §7's Glass column, the glass
language everywhere, real blur rationed). Six claims in the text are wrong against the code or the
maths and would ship as an invisible toggle knob, a bar you can't read over a pale photo, a test
that passes with no line drawn, an icon that isn't the one on the board, and an e2e run that is red
on two tests the spec says don't change. The biggest simplification: the spec's "content scrolls
beneath them" is false for list groups and the panel — nothing is behind an in-flow surface but the
frame gradient, so a translucent fill *without* blur is pixel-identical to the mock there. Blur only
the two sticky surfaces; the budget question disappears. Paste-ready text is in §4, the e2e list in §5.

## 2. Judgements asked for

1. **Tokens.** Glass column (S3). The Graphite recommendation predates G1; with an ambient wash and translucent fills, `text-3` needs the lifted `#8C8F94` and the darker ground. Numbers: Glass 4.73:1 vs Graphite 4.20:1 at the wash's peak.
2. **Primary.** Ivory fill. §7's glass + 55 % hairline primary reads as a large secondary in `mono-glass.png` ("Export"); the mono-compare Graphite column shows the filled one is the only thing that pops. The fix for the hierarchy problem is not the primary but its neighbours: segmented selected = lighter neutral, not ivory (S2 table).
3. **Blur budget.** As written (route-scoped `.list-group`): Parts root 4, folder 4, search results 1 + N sections (N = matching folders; the A13 fixture yields 3–4, so 5 on a normal search, 6 in Edit), picker 2, create form 2, Part 2 (+ the Faces edit list if the selector leaks), Capture 1, Annotate 2 (panel + a leaking Dimensions group = a stacked blur), Settings 1, Debug 1, Edit mode 4. Search results is over budget and the panel/Dimensions pair stacks — both blockers under the spec's own rule. Recommended (B1): every screen is bar + footer-while-editing = 1 or 2, nothing stacks, and the groups look as the mock does.
4. **G5.** Assertions: `parts.spec.js` "the root lists only its own parts and its subfolders; search is flat and global; rename moves into a folder" (:191-192) and "one folder per screen: rows, bar shape, Back, reload in place, "+" presets the folder, New Folder nests here" (:747 count 0, :782-783 count 1). `shell.spec.js` asserts Timers/Viewport only; `a11y.spec.js` uses `features-list` by testid, no heading. Hiding rather than removing keeps all of them. "Features · n" can go visually: the empty state is a separate branch (`No dimensions captured yet.`, Part.res:426), so nothing reads oddly; the count is the one datum the rows don't state, and the owner asked for the minimum — hide it, keep it for VoiceOver.
5. **Overlay palette.** Constants module, yes (`Draw`/`Render` already take plain strings); place it in `src/app/` (S5). 70 % holds for lines only if the pill leaves the alpha group (B4): §7's 3.4–3.7 is the pill *inside* the group at 60 %; outside it the label is 9.4:1 on white.
6. **Legibility window.** B5. Predicate and titles in §4.
7. **Icon.** Fits the real safe zone, not the one the spec states; doesn't match the board; θ at 16 px. Numbers in S1.
8. **Reduced transparency.** Not on iOS, verified against caniuse today (Safari/iOS 27.x "not supported"; Chrome 118+; Firefox flagged). Confidence high. Use `prefers-contrast: more` (works on iOS) now; an in-app toggle is worth doing but is scope (S8).
9. **Cost.** Two agents in parallel, disjoint files (§4 S10): tokens + materials + headers; overlays + icon + export test. Docs and LOGBOOK go with agent 2 after agent 1 lands (both would append to LOGBOOK). Screenshot tour and the double suite run are the conductor's.
10. **Ambiguities.** §4 J10.
