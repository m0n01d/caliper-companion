# SPEC §8a A17 (Adaptive layout) — pre-build review, 2026-09-18, commit `9548824`

**Verdict: BUILD WITH EDITS, two agents in series.** The direction is right (three widths, a centred column, Part in two columns, Annotate side by side) and the boards under `docs/design/mockups/adaptive-after-*.png` show it holds up. Three things in the text would ship broken: the sticky aside on Part never sticks (a stretched grid child), the Annotate side-by-side page scrolls by 48 px and fights its own panel scroller, and the hover e2e cannot pass under the chromium project's touch emulation. Layout claims were **measured in the repo's Playwright Chromium** (scratchpad probes, `setContent` pages using the real tokens; WebKit cannot launch here, e2e/README.md:6). Code claims cite the files. Paste-ready text in §4, the e2e list in §5, the boards in §6.

## 2. Judgements asked for

1. **Breakpoints.** 600 / 1024 are right for phones vs iPads vs desktop. iPad mini 744, iPad 820, Air/Pro 11 834 → medium in portrait, expanded in landscape (1133–1210); 13-inch iPads → expanded in both (S6: key Annotate on aspect too). iPhone landscape → medium (S5). 834 in medium is right: a 720 column with 57 px margins, 216 px cards, a 786 × 657 stage. Split View / Stage Manager windows fall where their width says. HIG's compact / regular is two classes because UIKit expects a split view at regular; three widths are the honest web version until A17b.
2. **Centred column.** S8: one padding line aligns the bar's grid to the column, no DOM change. The bar strip stays full-bleed (HIG); its contents follow the column. Column ownership: S2.
3. **Part expanded.** S3 names the DOM. Sticky is compatible with `.shell` as the one scroller — B1 is the only trap. Container query: S4, not needed.
4. **Annotate expanded.** S11: the canvas sizes from its box via `ResizeObserver`, A6 re-fits, snap radii scale, export unaffected. B2 fixes the height chain; the panel's own scroller is fine once the page has nothing to scroll; the footer slot is unused on Annotate. Keyboard: S12.
5. **Capture.** S9: keep the cards, 3-up, column-bound; no chip row (nothing to preview).
6. **Hover.** S1 (new token), N1 (timing), N2 (no double-ups; nothing today has `:hover`).
7. **Escape.** S7; exact shape §4 J6 — a `Main`-level subscription, not a Shell listener.
8. **Playwright.** B3 (touch emulation) and N5 (composition). Tour: S10, existing steps with a filter.
9. **Scope.** **A17-i** (sonnet): tokens + breakpoints, Shell `~column` + Main mapping, column CSS, bar/footer padding, Part columns (Part.res + Part.css), Capture column, hover, `adaptive.spec.js` Parts/Part/hover cases, DESIGN §12. Risk: low–medium (B1 in text). **A17-ii** (sonnet, after i lands — it needs `--cc-bar-height`, `Bleed` and the spec file): Annotate medium + expanded (Annotate.css only), Escape (WebApi + Main + three pages), the two Annotate and the Escape e2e cases, `TOUR_ONLY` + the eight wide PNGs, LOGBOOK. Risk: medium (B2, keyboard on a real iPad). Shared files: `theme.css`, `adaptive.spec.js`, `DESIGN.md` — serial, so no conflict. **Drop for a first iPad look:** the container query, `--cc-card-max`, Capture 4-up, Escape (no iPad benefit without a hardware keyboard — it ships in ii regardless), arrow keys (already A17b).
10. **Ambiguities for the builder** — resolved in §4: class names (`.part-columns`, `.part-gallery`, `.part-aside`, `data-column`), the column owner (S2), sticky offset (B1), `--cc-bar-height` (B2), `--vv-height` vs `100dvh` (S12), empty states: `Part not found` / `Loading` render outside `.part-columns` (Part.res:553-559) and stay single-column; the empty gallery is one dashed card; `parts-empty` and `folder-missing` sit in the 720 column unchanged; the `NotFound` Annotate branch (`.annotate-missing`) is not a grid.
