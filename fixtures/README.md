# Fixtures

## hinge_pin/

Synthetic "photos" generated by `node fixtures/make-fixtures.mjs` (bundled Chromium; no image
library dependency). Each is a flat background, a bar-shaped part, and a dark circular hole.

| file       | stored size | EXIF orientation | oriented size (after `from-image` decode) |
|------------|-------------|------------------|--------------------------------------------|
| `top.jpg`  | 1600×1200   | none             | 1600×1200                                  |
| `side.jpg` | 1600×1200   | none             | 1600×1200                                  |
| `end.jpg`  | 1600×1200   | 6 (rotate 90° CW)| **1200×1600** (portrait)                   |

The hole centre is at normalized **(0.30, 0.45)** of the *stored* pixels in all three. For
`top.jpg`/`side.jpg` that is also the oriented position. For `end.jpg`, rotating 90° CW maps a stored
normalized point `(sx, sy)` to oriented `(1 − sy, sx)`, so the hole is at oriented
**(0.55, 0.30)**. A tap on the hole in a correctly oriented viewer must yield ≈ (0.55, 0.30); a viewer
that forgot orientation yields (0.30, 0.45) or the wrong aspect. That is the M3 EXIF test.

`features.json` is the golden export for the fixture part (M1 `FeaturesDocument.make` must match it
byte-for-byte with injected dates; M5 re-export must match it except `exportedAt`).
